# Ad rules for qq-bot — a single file with three sections, unioned with the
# built-in lists in src/ad/. Edit and push to update a live bot (no redeploy);
# a failed fetch keeps the built-in lists in effect. Lines starting with "#" are
# comments; blank lines are ignored.
#
# [keywords]  one term per line. General terms — each hit is weak evidence,
#             weighted by a likelihood ratio. Generic words alone (客服, 咨询,
#             QQ, …) never reach the flag threshold.
# [strong]    one term per line. High-signal contact/promo/spam words that are
#             almost never benign — each hit is strong evidence, so a strong hit
#             plus any other keyword typically flags.
# [patterns]  one regex per line — a bare source, or the /source/flags form.
#             A single match flags a message. Patterns are validated at load:
#             invalid, over-long, or catastrophically-slow ones are skipped and
#             the stateful g/y flags are dropped.
#             WARNING: patterns run on every message with no timeout. Avoid
#             nested quantifiers like (a+)+ which can hang the bot (ReDoS).
# [variants]  variant words (变种词): one line per canonical keyword, mapping
#             deliberately-obfuscated spellings to the real keyword. A matched
#             variant is scored as a strong hit of the canonical keyword and
#             multiplied by the variantLr weight (变种词权重) — obfuscation is
#             itself ad evidence. Format: 原词=变种1|变种2|...
#             微信=薇信|威信|vx
#             博彩=菠菜|bo彩
#             These append to (not replace) the config/ad.json variantKeywords.
#
# Tuning: the forbidden words, intensity and probability params live in
# config/ad.json (raise threshold or minKeywordHits for fewer flags, lower them
# for more). This file only *adds* live terms on top of that base.
#
# Keyword seed derived from konsheng/Sensitive-lexicon (MIT License),
# https://github.com/konsheng/Sensitive-lexicon — Copyright (c) konsheng.
